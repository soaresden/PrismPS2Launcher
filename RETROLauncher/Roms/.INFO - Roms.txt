RETROLauncher fork - folder layout
==================================

One folder per system, short EmulationStation-style names. Each one holds its
own ROMs, artwork and titles, so a system is entirely self-contained and can
live on the USB stick or on the internal exFAT disk indifferently.

    Roms/megadrive          Sega Megadrive / Genesis
    Roms/mastersystem       Sega Master System
    Roms/gamegear           Sega Game Gear
    Roms/sg1000             Sega SG-1000
    Roms/nes                Nintendo Famicom / NES
    Roms/snes               Nintendo Super Famicom / SNES
    Roms/gb                 Nintendo Game Boy
    Roms/gbc                Nintendo Game Boy Color
    Roms/gba                Nintendo Game Boy Advance
    Roms/atari2600          Atari 2600
    Roms/lynx               Atari Lynx
    Roms/ngp                Neo Geo Pocket
    Roms/APPS               homebrew and .elf
    Roms/psx-ember(bin and cue)   PlayStation, .cue + .bin, run by Ember
    Roms/psx-pops(vcd)      PlayStation, .vcd, run by POPStarter
    Roms/ps2-isos           PlayStation 2, .iso, run by Neutrino

Alternative names are still accepted (genesis, sms, gg, famicom, fds, sfc,
gameboy, atarilynx, sg-1000, ngpc...), as are the original long names of the
upstream project.


Inside a system folder
----------------------

    Roms/gb/Tetris (World).zip
    Roms/gb/media/covers/Tetris (World).png
    Roms/gb/media/screenshots/Tetris (World).png
    Roms/gb/titles.txt

Artwork is named after the ROM file without its extension. "titles.txt" holds
one "file|title" pair per line and makes the launcher display the real game
title instead of the file name.

Both are generated by HelperScripts/MediaCopier.py from a Batocera, Recalbox or
EmulationStation install.


Image requirements
------------------

From the RETROLauncher manual, and they are not negotiable:

    The image MUST have an alpha channel. A PNG without a transparency mask
    is loaded and then silently ignored - no image, no error. Artwork scraped
    from Batocera or produced by OPL usually has none.

    Resolution below 320x240. Higher works but costs performance, and the
    console only has 4 MB of video memory for the whole interface.

    The smaller the file, the smoother the browsing.

MediaCopier.py enforces both: every image is re-encoded to RGBA and fitted in
a 320x240 box. It needs Pillow for that - "pip install pillow" - and warns
loudly if it is missing.

PlayStation 2 artwork is the exception: it is not copied at all. OPL keeps it
in "ART" at the root of the drive, named after the game ID (SCES_502.40_COV.png,
_SCR.png), and the launcher reads that folder on every drive, including the
internal exFAT disk. MediaCopier only offers to add the missing alpha channel
to those files, in place. OPL still reads them afterwards.


Shared resources
----------------

    Roms/!Retrolauncher/Background      custom backgrounds
    Roms/!Retrolauncher/Font            custom fonts


System files
------------

They all live in "Bios/" at the root of the launcher:

    Bios/psx-ember.elf      the Ember emulator
    Bios/bios.bin           PlayStation BIOS (scph1001.bin from Batocera, renamed)

Ember is the one exception to the "everything in Bios/" rule, and not by choice:
it resolves the .cue relative to its own directory and is given the bare file
name, so it has to sit next to the games. The launcher copies "ember.elf" and
"bios.bin" from Bios/ into "Roms/psx-ember(bin and cue)/" the first time a PS1
game is launched from that folder. Two small files, once.
    Bios/gba_bios.bin       Game Boy Advance BIOS
    Bios/POPS/              the four POPStarter binaries, kept here as a copy

POPStarter itself requires POPS.ELF, POPS.PAK, POPS_IOX.PAK and IOPRP252.IMG in
a "POPS" folder at the ROOT of the drive, not inside the launcher folder. The
copy under "Bios/POPS" is there so the set travels with the install;
MediaCopier.py can deploy it to the right place.

None of these files are distributed with the fork.

A note on PlayStation
---------------------

Two folders, two emulators, two formats. Ember takes .cue + .bin and runs from
the launcher. POPStarter takes .vcd, only from USB, and needs its binaries at
the root of the drive — no SMB, no HDD.
